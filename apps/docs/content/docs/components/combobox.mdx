## Composition

### Simple

A single-line input and a flat list.

```text
Combobox
├── ComboboxInput
└── ComboboxContent
    ├── ComboboxEmpty
    └── ComboboxList
        ├── ComboboxItem
        └── ComboboxItem
```

### With chips

Multi-select with `multiple`, chips, and a chips input.

```text
Combobox
├── ComboboxChips
│   ├── ComboboxValue
│   │   └── ComboboxChip
│   └── ComboboxChipsInput
└── ComboboxContent
    ├── ComboboxEmpty
    └── ComboboxList
        ├── ComboboxItem
        └── ComboboxItem
```

### With groups and collection

Nested items per group using `ComboboxCollection` inside each `ComboboxGroup`, with a separator between groups.

```text
Combobox
├── ComboboxInput
└── ComboboxContent
    ├── ComboboxEmpty
    └── ComboboxList
        ├── ComboboxGroup
        │   ├── ComboboxLabel
        │   └── ComboboxCollection
        │       ├── ComboboxItem
        │       └── ComboboxItem
        ├── ComboboxSeparator
        └── ComboboxGroup
            ├── ComboboxLabel
            └── ComboboxCollection
                ├── ComboboxItem
                └── ComboboxItem
```

## Design

<DesignGuidelines>

### When to use

- Choosing from a large set of predefined options where typing to filter helps, such as a city, a language or a product category.
- Lists too long for a [Select](/components/select) to stay easy to scan.

### When not to use

- Short lists that are easy to scan. Use a [Select](/components/select).

### Guidelines

- Write a message for when nothing matches the search, such as "No framework found," rather than leaving the list empty.
- Make clear whether the user can only pick from the list or can also enter their own value. If they can't, say so in the placeholder or the description.

See also: [Forms](/design/forms).

</DesignGuidelines>
