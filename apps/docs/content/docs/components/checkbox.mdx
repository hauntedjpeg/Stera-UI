## Design

<DesignGuidelines>

### When to use

- A yes-or-no choice, such as accepting terms, opting into a feature, or enabling a setting that's saved with a form.
- In a group, selecting any number of items from a list, such as filters or preferences.

### When not to use

- Mutually exclusive options, where only one can be selected. Use a [Radio Group](/components/radio-group).
- A setting that takes effect the moment it changes. Use a [Switch](/components/switch).

### Guidelines

- Always pair a checkbox with a visible label. Add a description when the label alone doesn't explain the choice.
- Give a group of checkboxes a label that says what the set is for.
- Use the indeterminate state only for a parent checkbox whose children are partly selected.

See also: [Selection](/design/selection).

</DesignGuidelines>

## Composition

Use the following composition to pair a `Checkbox` with a label:

```text
Field
├── Checkbox
└── FieldLabel
```

To add a description, wrap the label and helper text in `FieldContent`:

```text
Field
├── Checkbox
└── FieldContent
    ├── FieldLabel (or FieldTitle)
    └── FieldDescription
```

To group related checkboxes, nest `Field`s inside a `FieldGroup` and `FieldSet`:

```text
FieldSet
├── FieldLegend
└── FieldGroup
    ├── Field
    │   ├── Checkbox
    │   └── FieldLabel
    └── Field
        ├── Checkbox
        └── FieldLabel
```
