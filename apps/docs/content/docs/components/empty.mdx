## Design

<DesignGuidelines>

### When to use

- A list, [Table](/components/table) or container with no records, because none exist yet or because a filter or search returned nothing.
- Guiding users to a next action, such as creating their first record or clearing a filter, instead of leaving a blank surface.

### When not to use

- Content that's still loading. Use a [Skeleton](/components/skeleton) or a [Spinner](/components/spinner).

### Guidelines

- Every empty state needs a title and a short description that together say what's missing and why. An icon, an [Icon Tile](/components/icon-tile), an illustration or an [Avatar](/components/avatar) can reinforce the message, but never replaces it.
- Match the action to the cause. After a filter or search, help the user recover, such as Clear filters. For a dataset that's genuinely empty, prompt them to create something, such as Add project.
- Keep the tone helpful and direct, never negative or apologetic. An empty state orients the user; it doesn't report a failure.

See also: [Loading and empty states](/guidelines/choosing-components#loading-and-empty-states).

</DesignGuidelines>

## API Reference

### EmptyMedia

| Prop | Type | Default |
| --- | --- | --- |
| `variant` | `"default" \| "icon"` | `"default"` |

### Subcomponents

| Component | Description |
| --- | --- |
| `EmptyHeader` | Centered container for media, title, and description |
| `EmptyMedia` | Slot for an icon or avatar illustration |
| `EmptyTitle` | Heading text |
| `EmptyDescription` | Supporting body text |
| `EmptyContent` | Slot for action buttons below the header |
