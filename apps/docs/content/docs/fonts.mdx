title: Fonts
description: How the CLI sets up fonts and how to change them.
---

Stera UI reads three font roles from `ui/typography.css`. That file is exported from the Stera UI Figma file, so the fonts it points at are the source of truth for which fonts get installed.

```css title="styles/ui/typography.css"
:root {
  --font-heading: var(--font-zalando-sans-semiexpanded, sans-serif);
  --font-sans: var(--font-zalando-sans, sans-serif);
  --font-mono: var(--font-geist-mono, ui-monospace, monospace);
}
```

Each role points at a variable named after a font family, with a fallback for when no font is loaded. `--font-sans` is body text and Tailwind's `font-sans`, `--font-heading` is for headings, and `--font-mono` is for code and Tailwind's `font-mono`. Each `st-*` utility uses the role its Figma text style is bound to.

## What `init` does

`init` asks whether to install the Stera UI fonts, and records the answer in `stera.config.json` under `fonts.strategy`. With `--yes` it installs them.

| Choice          | Behavior                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stera-default` | Installs every font `ui/typography.css` references (today Zalando Sans SemiExpanded, Zalando Sans and Geist Mono). Your existing fonts stay loaded for your own code. |
| `skip`          | No font work. `init` prints the role lines to edit and any `next/font` variables your layout already loads.                                                           |

`init` finds each font by its variable: `--font-zalando-sans` is the `font-zalando-sans` item in the registry.

### Next.js

`init` loads the fonts with `next/font/google` in your root layout and puts their variables on `<html>`:

```tsx title="app/layout.tsx"
const zalandoSans = Zalando_Sans({
  variable: "--font-zalando-sans",
  subsets: ["latin"],
})

// …
<html className={`${zalandoSans.variable} ${geistMono.variable}`}>
```

Fonts your layout already declares under the same variable are reused as they are. If there is no `app/layout` (the Pages Router) or no `<html>` element, `init` prints the code to add yourself.

### Other frameworks

`init` installs the `@fontsource-variable/*` packages and writes `ui/fonts.css`, which imports them and defines the family variables. Your `globals.css` imports it next to `ui/index.css`:

```css title="styles/ui/fonts.css"
@import "@fontsource-variable/zalando-sans";

:root {
  --font-zalando-sans: "Zalando Sans Variable", sans-serif;
}
```

`ui/typography.css` is never edited, so refreshing it with `stera-ui add globals` keeps your fonts working.

### Styles that override the fonts

Some starter templates set fonts in `globals.css` that win over Stera UI's. create-next-app ships both of these:

```css title="app/globals.css"
@theme inline {
  --font-sans: var(--font-geist-sans);
}

body {
  font-family: Arial, Helvetica, sans-serif;
}
```

`init` warns about `--font-*` entries in `@theme inline` and `font-family` on `html`, `body` or `:root`, with their line numbers. It doesn't edit `globals.css`. Remove the lines to use the Stera UI fonts everywhere.

## Adding another font

Fonts in the registry install with `add`, the same way `init` loads them:

```bash
npx stera-ui add font-inter
```

Then point a role at its variable in `ui/typography.css`:

```css
--font-sans: var(--font-inter, sans-serif);
```

Run `stera-ui list` to see the available fonts.

## Using your own fonts

Skip font setup, load your fonts however your framework does it (`next/font`, fontsource, `@font-face`), and point the three roles at them. Stera UI only reads the roles.
